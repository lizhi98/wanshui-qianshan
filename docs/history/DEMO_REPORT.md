# 《万水千山：战火中的木板》交付报告

2026-10-14。实测引擎 `4.6.stable.official.89cea1439`；Windows；RTX 4060 Laptop；OpenGL Compatibility。

## 交付与结论

独立 Godot 工程、Windows x64 EXE、便携引擎与模板、操作说明、测试脚本、日志和截图已交付。EXE 内嵌资源，无需安装 Godot 即可游玩。

从开场、两名守军战斗、拾板搬运、阿木协作铺板、铁索通行，到战友会合、结局与结算，已经完成带画面的实际输入驱动自动通关。此结果证明现成控制器、骨骼模型、动作、战斗和物理碰撞可以整合为完整可玩关卡。

目前美术为风格化低模，人物服装与动作仍有明显简化，不能据此认定已达到正式历史动作冒险游戏的视觉品质。精确瞄准的自动测试通关约 88—90 秒；未进行真人手感验收，需求中的人工游玩约 3—5 分钟尚未验证。

## 1. 真实实现

- 继承 Kenney 第三人称控制器，复用相机相对移动、速度平滑、重力、CharacterBody3D 碰撞；加入奔跑、鼠标镜头、瞄准、障碍回缩。
- 五名实际 skinned mesh 人形角色，Skeleton3D、AnimationPlayer、帽子、背包、长枪与区分服装。没有用方块堆叠替代人物。
- 26 米桥段、两岸、峡谷山体、铁索、木板、两个物理缺口、掩体、树木、旗帜、烟雾、运动河面、阳光阴影和材质。
- 生命、五发弹匣、备用弹药、装填、补给；枪声、枪口光、弹道、命中提示、受击与后坐力。准星射线确定目标，枪口第二条射线检查近处掩体。守军按距离和真实视线攻击，死亡停止；周班长实际瞄准开火压制。
- 拾板时调整位置、下蹲弯身、手部接触；木板绑定 CarryAnchor，搬运减速。阿木沿路径到协作点；人物与木板同步放下，完成后启用 StaticBody3D，真实改变可通行区域。入口和新木板顶面已与旧桥面找平。
- 可操作预设铁索路径：W/S 前后移动、A/D 平衡，人物侧身扶索、脚步、身体摇摆、河流视野；失衡和坠落可失败。
- INTRO → COMBAT → PICKUP → COOPERATE → CROSSING → ENDING 门控；对白、搬板与攀索锁住冲突操作；三阶段检查点、暂停、失败重试、完整重玩恢复。
- 所给对白、任务、开场与结束镜头、诗句和五项结算均已接入。

## 4. 骨骼动画与程序动作

骨骼素材：Idle、Walk、Sprint、Jump、Hit_Chest、Death01、Pistol_Reload；瞄准使用 Pistol_Idle 后补长枪姿态。拾板/铺板使用 Fixing_Kneeling，调整采样速度与上身姿态。

动作适配：按同名骨骼转移旋转，保留目标休息姿态的肢体长度，再转移 pelvis 位移动量。Godot 会剥离 _Loop 名称，脚本已补原名称别名与循环设置。

程序部分：两骨骼手臂解算、手腕朝向、弯腰、拿板位置对齐、木板父节点与放板轨迹、扶索目标、侧身和平衡、NPC 路径、镜头、河流和旗帜。铁索脚步复用行走，不是专门制作的攀索动画。

## 5. 是否完整通关

是，输入驱动图形通关脚本已实际运行并到达结算。战斗未完成不能修桥；修桥改变碰撞；攀索没有黑屏传送。另用边界测试覆盖失败重试和完整重玩。人工游玩、任意路线和发布版长时间运行尚未验收。

## 6. 明显问题与简化

人物仍较健壮，军装主要是材质和附加装备，缺少真实剪裁、布料和时代细节。动作过渡、脚部接地、手指、袖口与装备仍可能滑动或穿插；末段接触检查不代表每一帧均无问题。

环境是程序低模，河流波纹重复，烟雾为简化粒子。守军没有巡逻、换掩体或高级战术；NPC 按预设路径行动，不做动态寻路。铁索没有完整承重、断裂和物理摆动。字幕没有配音、口型和表情演出，音效混音与镜头过渡仍可继续打磨。

没有单独保存七个不同阶段的成品；保留原版、第一次可通关 Git 标签 functional-slice-v1，以及最终标签 delivery-v1。

## 7. 影响完整长征游戏的困难

需要投入普通比例历史人物/服装、专用搬运协作和攀爬动作、AnimationTree 与上半身混合、接地 IK、稳定的重定向流程、历史审校、配音、环境资产库、长关卡寻路和性能管理。一次短关通关不能证明整款游戏的美术成本和开发周期已经可控。

## 8. 后续可复用

可复用控制器继承方式、镜头、双射线战斗、生命与武器状态、骨骼素材适配、手部目标、任务门控、检查点、字幕 HUD、结算、测试和 Windows 导出。当前关卡坐标和对白仍为手工编排；扩展雪山/草地时，应把路径、交互点、对白与敌人配置抽成可编辑资源。
