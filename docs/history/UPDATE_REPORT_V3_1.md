# V3.1 修改与验证

攀索的旧实现使用静止蹲姿和固定双手目标；新实现按移动距离计算交替接触，手与脚分别经历支撑、放开、前伸和重新抓握。身体向铁索靠近，配合轻微重心变化，避免手臂超出可达长度。停止移动后抓握周期停止。

原桥上队列使用同一中心目标、统一速度和固定停车距离。新实现采用分批生成、速度差、错位等候点、局部让路与短时掩护射击。需要修复的缺口前仍会停在安全范围，通道开放后继续冲锋；没有让战友无视缺口直接冲入水中。

两岸炮组、炮弹、爆点和步兵射击由独立的有界场景模块驱动。背景演出不会代替玩家完成主线敌人的击倒、修桥或观察任务。烟尘、火光与水花会结束并释放；暂停会冻结炮组、弹道和粒子，回标题会清理正在发生的场景交火。

配乐从低强度长音草图改为四段原创编配：108 BPM 行进、124 BPM 冲锋、114 BPM 攀索危机、96 BPM 胜利。使用 GeneralUser GS 乐器渲染，具有铜管主题、弦乐进行、军鼓滚奏、低音与镲的段落变化；新的冲锋母带 RMS 约 -17.7 dBFS，原紧张草图约 -34.3 dBFS。游戏内还按对白状态衰减配乐，母带强度不是最终扬声器声压。

查阅了央视电影页面、所引片段资料及公开影片抽样画面。影像中分工掩护、机枪阵地、推进与桥头火势作为调度参考。新增旋律与具体编配是本次创作选择，不声称凭网页资料完成了电影原声的乐器逐轨听辨或精确复刻。

已验证：攀索时握持手的世界坐标支撑、相对身体的换抓、停止后的脚步稳定；两岸均发生 NPC 炮击与落点效果；有步兵交火；场景角色、弹道和特效数量有上限；暂停与标题退出；原有修桥、攀索、提示、配音队列及通关输入流程。实机录像从标题走到 V3.1 通关结算。

少量旧测试在退出时仍有 Godot 资源回收警告，检查断言通过；图形录制和主线回放单独核验。完整日志与视频对应的程序哈希随交付提供。画面采用原工程风格及简化模型，并非电影级写实画面。
