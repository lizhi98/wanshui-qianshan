# V4.1.3 人物动作专项修复

本版基于完整 V4.1.2 独立副本修改。第一关、六幕剧情、指挥员怒问、身份揭晓、十人敬礼、B版自然剧情男声、六段音乐和指定片尾文字均保留。没有新增 NPC、章节、配乐或玩法。最终验证数据见 `V4.1.3_TEST_REPORT.md`，录像是渲染后的 Windows 程序画面。

## 证据与旧测试的盲区

已读取原 6分52秒完整录像、营地3.37秒和爬山5.07秒录屏。两段短片按原30fps解码为101、152帧，逐帧联系表复核肩臂、腿部相位和身体高度；完整录像重点复核2:40—3:35行军及4:30—5:45现场。用户指定桌面文件夹内实际只有上述两段短片，没有新的两张图片；未将缺失图片标成已查看。已有旧现场图与相同四机位坐姿夹具另作对照。

V4.1.2的98项检查证明交付、任务、对白、到点和结算能够运行，敬礼的逐骨骼检查主要测右手末端是否靠近帽檐。它们没有检查完整步态周期、上下肢相关性、实际位移与动画速度是否相符，也未测连续支撑足滑动或真实鞋底。因而不能从“98 PASS”推出动作自然。

修复前另采集900帧、11个演员的根节点与骨骼轨迹。原始 Walk 资源交叉手脚相关系数0.967/0.978；原游戏 Player/Amu只有0.046/0.049。只移除冲突的程序腿部步态，便恢复到0.962/0.960，证明问题来自覆盖层，而非左右骨骼映射损坏。

## 清障后的 T 形姿势与验收补漏

第二轮完整录像虽然通过98项流程检查和原120项运动指标，逐段看画面时仍发现清障后主角双臂持续平举。单独执行“清障6秒→待机3秒”能稳定复现：动作树引用不存在的`Push_Loop`，有效资源实际名为`Push`；错误动作节点会让后续基础树保持Rest姿势，即使动作混合已经归零。修复为复制已有`Push`资源并明确启用循环，以`Memorial_Clear_Loop`绑定清障节点，不修改共享桥关动画资源。

旧C夹具遗漏了清障转换，交叉肢体相位只在走路段检查，也没有在待机检查手臂高度，因此这些PASS不足以发现本次缺陷。新增清障、清障后待机与行走三个阶段，并检查恢复待机的手部高度及臂展，保留逐帧连续性与步态检查；对11名主要角色运行时构建的动作树递归审计297个动画引用。修复前后的真实渲染与骨骼日志独立留存。第二轮含缺陷的完整录像撤出交付，最终视频全部重新从修复后的同一Windows程序录制。

## 控制所有权与模块边界

录制器另有一项独立问题：Windows将原生窗口判定为遮挡时，Godot主循环仍更新游戏并写入视频帧，但可能不重新绘制，C片段后半段因此重复旧图像。根据Godot 4.6主循环源码，绘制受`can_any_window_draw()`门控，MovieWriter写帧在该门控之外。通过最小化窗口的25秒对照实验，帧末`RenderingServer.force_draw(false)`可使录制图像继续更新。`qa/movie_capture.gd`仅在MovieMaker模式启用，不改变游戏时间、人物位置、动作或输入；交付另核验刷新次数与视频帧数。NPC夹具的概览镜头增加地表净空检测，避免固定测试机位落入山坡。它不替换正常第三人称相机。

`player.gd` / `npc.gd`：物理位移、重力、朝向；剧情只请求朝向或提交路线和动作。原桥关及旧雪山控制器保留，仅在雪山基类增加默认 `_player_type()` 工厂钩子。

`visual.gd`：完整人体基础动画、专属搬运/叙事动作、动作恢复。`contact_ik.gd`最后处理地形接触，既不生成正弦步态，也不移动物理根节点。原地转身复用已有步行动作，未增加新的专业转身动捕。

`NavigationAgent3D`只计算局部避让速度，不调用它的路径移动逻辑，不写根节点坐标；物理控制器使用结果。实现依据[Godot 4.6 NavigationAgent说明](https://docs.godotengine.org/en/4.6/tutorials/navigation/navigation_using_navigationagents.html)，保留原路线、任务和检查点结构。

## 验收边界和仍存在的限制

数值通过与实机观察分开报告。A/B/C/D是明确摆放的测试夹具；E才是从标题到结算的普通输入自动回放，使用移动、观察、交互和信号，未设置完成变量、传送演员或跳过剧情。它不冒充真人手动试玩。

本版保留原有模型、面部和动画库。衣物没有布料物理解算；没有专业多方向转身、急停动捕和精细面部表演；极端快速反向移动、崖边和镜头贴近人物时仍需人工体验。坡面IK按轻量两段腿链处理，不能保证任意地图、任意站位永无脚尖误差。远景简化角色的动作精度低于近景。

旧回归中的少数短命夹具在退出时仍打印原有ObjectDB/资源清理提示，单列日志保存；没有把它们伪装成动画断言失败，也没有忽略运行中的脚本错误。测试脚本、阈值、异常角色ID/时间/位置及失败试验记录均保留。最终是否达到你希望的动作观感，以附带多机位视频和实际操作为准，不能用PASS数量代替。

## 首轮Windows录制的额外发现

首轮30fps渲染录制出现一次小田落在(-7.52,22.47,-44.89)而不再前进，阻止现场集结。失败录像、检查点和日志保留，未作通过证据。同一程序资源包在30fps无画面和带画面回放均曾连续通过；单独恢复该检查点也能继续行走。82个胶囊的坡面投影对照实验没有复现，因此不能把底层原因断言为某个Jolt设置或陡坡角度。现版在无人阻挡、持续有移动意图却停滞时，重新提交从当前物理位置到同一剩余路点的通行段并刷新局部避让；保留位置、路点序号、碰撞和任务状态，恢复加速，并记录重规划次数。邻近队友的正常排队不触发。补充了无传送、不跳点、冷却和正常排队五项检查。它是有记录的停滞恢复措施，底层偶发原因仍未完全复现，应保留为后续人工压力测试项。最终录像和检查结果以交付测试报告为准。
