# 泸定桥 V2.1 修复与验收报告

日期：2026-10-28（北京时间）。本交付在用户提供的完整源码上修改，未重建游戏。Windows 程序为 Godot 4.6 stable x86-64，PCK 内嵌。原场景、美术、骨骼、动画、六章任务、战斗、攀索、观察选路、数字重建和检查点继续保留。

## 工程结构与录像核对

- 主入口：`game/v2/main.tscn`；任务编排 `game/v2/campaign.gd`。
- 玩家：`game/v2/player.gd` → `game/player.gd` → 原 Kenney `scripts/player.gd`；CharacterBody3D、相机相对 WASD。
- NPC：`game/npc.gd`；原路径按手工航点移动。此次接应增加 `game/v2/carry_navigation.gd`，不替换其他章节的既定路线。
- 动画：原 GLB 人物、53 骨骼、AnimationTree、动作混合及双臂 IK，主要在 `game/remaster/character_visual.gd`、`game/soldier_visual.gd`。
- 世界：`game/v2/world.gd` 继承原程序生成的历史场景；搬板任务 `game/v2/repair.gd`；场景不是外部 Unity/UE 工程。

## 根因与实际修复

1. **队友卡住连带锁死玩家。** 原搬运 tick 按队友落后距离大于 3.6 米设置玩家锁定；现在寻路不决定玩家移动权限。接应期间自由移动；只有共同抬起/放下的短暂动作锁定位置，且可 R 取消。不可达 18 秒超时回到可重试状态。
2. **碰撞回滚造成退不出的姿态。** 原木板重叠时回滚玩家整个 Transform，并清空速度；现在在玩家实际位移前对木板与队友占用范围扫掠，阻止危险运动，保持当前有效位置，允许退让、侧移和 R 重试。持续尝试被挡 8 秒自动释放。静止等待不会因计时被强制取消。
3. **未到位就单人举板。** 呼叫、寻路、两端到位、同步抬起、共同搬运、放下、固定检查各自有状态。只有队友实际到达另一端，玩家站稳握点后才抬板。
4. **木板、人物和 IK 各自更新导致错位。** 搬运阶段使用一个稳定基准确定板、两名搬运者和四只手的目标；玩家物理移动先更新，再同步搬运基准。保持碰撞扫掠与边缘支撑检测，不使用 NPC 的物理推进结果反向锁玩家。
5. **无全局绕行能力。** 接应改为基于实际地面与胶囊体净空构建的 0.35 米局部 A* 图；0.8 秒不前进时重规划，端点不可达则保留玩家控制并给出超时恢复。不会用隐蔽瞬移冒充成功寻路。
6. **旧阶段障碍遗留。** 战斗结束的掩体、箱子、补给以及观察阶段的 ReconCover 原来仍在搬运路线中；现在按任务阶段同步隐藏和关闭碰撞。战斗/观察阶段继续保留其作用。去掉原搬板任务刻意设置在路线上的高物资架与倒木，只留河岸边一处小物资堆；减少桥面装饰碎木与远处重叠材料标签。桥、地图桌、房屋、旗帜、山体等保留。
7. **动作和退出状态不完整。** 保留已有动作混合与 IK；共抬时不再瞬时按输入反转角色；停止时速度归零，暂停冻结动画。放置采用先降低木板、再从近侧支撑位置送上桥面的分段动作，绕板移动时释放不可达手部目标。所有取消、完成、死亡/恢复都会清除搬运标志和手部约束。
8. **只有字幕、没有对白。** 已离线生成 32 条中文 WAV，添加单通道语音队列、重复抑制、对应字幕、说话嘴部提示、暂停/恢复和背景音乐压低。修复了一处在语音结束信号前抢先切换下一句的竞态，语音测试复测通过。保留并使用原木质抬放声、脚步、河流和风声。
9. **发布兼容。** 修复标准版 Godot 导出时误收 C# 插件示例的问题，只从发行包排除这些未使用示例，源码仍保留。游戏内部应用名保持原值以沿用原存档目录，窗口和菜单标识 V2.1。

## 搬运状态与恢复

`select → position/tie/check → pickup → join → npc_ready → lifting → carry → lowering → align/secure/place_check → 下一处 / done`

- E 要求靠近实际木料/握持点，距离太远不触发。
- 呼叫后玩家走开会取消，不会把木板远程带走。
- 寻路失败重规划，最终超时释放，R 也可随时退出操作。
- 放置只在目标区域允许，放下过程中重复 E 不跳过动画。
- 中断存档统一归一为备料点 `pickup`，只有一个木板节点；已修好的缺口保留。
- 完成后清除持板和 IK，重复交互不重复计分。
- 核心切换有 `[Carry]` 日志；内存仅留最近 80 条，避免无限累积。

## 中文配音与来源

32 条音频合计 117.3 秒，均为可解码、非静音的 22050 Hz / 16-bit PCM WAV。`assets/voices/manifest.json` 对应人物、台词和文件；`audio_validation.json` 记录时长、峰值、RMS 和 SHA-256。无空白音频或提示音冒充人声。

实际使用本机已有 Microsoft Kangkang，通过 Windows System.Speech 离线合成。周班长较低/慢、阿木较高/快、林川自然。无需 API、密钥或游戏运行时 TTS。独立配音包和中文台词表随交付提供。

边界：这三个角色共享同一个基础男声音色，通过韵律区分，尚不是三个独立声优或开源多说话人模型。尝试下载 Apache-2.0 的 AISHELL3/icefall 模型时，环境出现 DNS/网络失败，因此没有使用或虚报已使用。微软语音模型本身未随工程分发，也不宣称它具有开源许可；来源和使用范围说明在 `licenses/Chinese_Voices_Provenance.txt`。本轮满足实际中文音频交付，但没有完成“以独立可核验开源模型替代系统音色”的优选项。

## 剩余边界

- 本轮已验证的是这台 Windows / RTX 4060 环境；没有进行其他显卡、Windows 版本、手柄或长时间多人自由操作测试，不承诺所有机器零问题。
- 搬运采用程序同步与已有动画/双臂 IK，放置是游戏化的近侧送板动作，没有引入新的专业搬运动作捕捉或复杂真实受力模拟。
- 中文声学表现为系统合成，不是演员录音；开源多说话人音色与独立许可链尚未完成，详见上文。
- 第一版“20 次完成”的测量发现同步基准的一帧偏差，已经调整更新顺序，并以本报告引用的最新 20 次零失败日志替代旧测量；早期试验日志没有作为最终通过证据。
- 原 V2/V1 报告、素材来源清单保留作历史记录；当前验收以本文件及 v21 证据为准。
