# 钓鱼机制代码说明

## 结构与输入

`game/golden_hook/fishing_model.gd` 是不依赖场景树的规则层；`fishing_view.gd` 负责真实 3D 钓竿、双手目标、抛物线浮标、鱼线、水波、鱼和镜头；`chapter_state.gd` 验证故事及物品事务。规则层不直接发放物品。只有当前捕鱼任务收到一次 `caught` 信号，才能执行 `story.add_fish()`。

靠近当前岸边按 E 进入，玩家锁定走动，沿用原项目的 Camera3D。鼠标调整方位 ±0.72 弧度；左键按住蓄力，松开后按 `1.8 + power * 6.2` 米计算实际落点。落点必须在当前水塘的有效椭圆范围内，朝岸上抛会失败。Q 随时收竿。

## 状态机

| 状态 | 输入、表现和转移 |
| --- | --- |
| INACTIVE | 普通探索；只接受靠近当前岸边的进入请求 |
| PREPARE | 左键蓄力，松开抛竿；无效落点转 ESCAPED |
| CASTING | 0.65 秒可见抛物线飞行，再进入 WAITING |
| WAITING | 随机等待 2.4–4.2 秒；最后 0.85 秒有试探性轻晃；此时抢按空格会脱钩 |
| BITE | 浮标明显下沉，伴随声音；默认 1.15 秒内按空格可提竿 |
| HOOKED | 0.30 秒提竿动作，进入 REELING |
| REELING | 左键收线，松开缓线；持续计算张力、进度和脱钩条件 |
| CAUGHT | 进度达到 1，序列号加一并发出单次 caught；可见小鱼被拉至手边，2 秒后退出或继续 |
| ESCAPED | 给出具体原因；E 立即准备下一次，不扣鱼钩和任务物品 |

## 咬钩判定

`strike()` 只在 BITE 状态成功。WAITING 时提竿是过早失败，BITE 超过窗口是过晚失败。准备、飞行和已收获状态不能用空格跳过步骤。辅助设置可选 0.9 / 1.2 秒；初始默认 1.15 秒。

## 张力和收线

每秒张力变化：收线 `+0.225`，缓线 `-0.27`，叠加可预测的 `sin(clock*1.7)*0.025` 鱼挣扎项，限制在 0–1。张力 0.23–0.86 且收线时，进度每秒 `+0.152`；范围外收线每秒 `+0.035`；缓线每秒 `-0.012`。

张力 ≥0.96 累计 0.55 秒会绷脱；张力 ≤0.12 累计 2.4 秒会松脱。离开危险范围后，相应计时以每秒两倍速度回退，短暂碰到边缘不会瞬间判负。检查先判失败，再判进度满条，避免同一帧既失败又奖励。

规则测试中，张力达到 0.68 时放松、降到 0.36 时继续收线，在 20 个等待随机种子中均能完成，单次收线约 13.22 秒。这是规则验证，未将该策略注入正常玩法。

## 防卡关与唯一鱼钩

没有独立的随机空竿、随机断线或任务掉率；随机性只决定有限的等待长度。默认等待永远在 2.4–4.2 秒内结束。两次普通捕鱼和最后一次捕鱼都有明确任务上限，不能刷出额外任务奖励。E 不会直接调用 `add_fish()`。

中途退出、失败、返回标题或重新加载，都保留已获得鱼和已制作鱼钩，未完成的一次抛竿从 PREPARE 重新开始。核心道具 ID 始终为 `grassland_needle_01`。同一个 3D 鱼钩节点从工作台挂到浮标，再到遗落位置、玩家手中、布包和衣袋；重新开始前先将它从临时持物节点保护性移出，防止清理布包时删除关键道具。

## 证据边界

单元测试和摆位回归检查可以直接构造状态，以覆盖边界。完整输入回放 `tests/golden_hook/input_playthrough.gd` 仅读取状态决定键鼠事件；不设置故事进度、奖励、人物或镜头变换。两种验证在报告中分开记录。实际录屏包括一次故意提前提竿的失败、立即重试和三次有效捕鱼。
